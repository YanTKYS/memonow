# テスト・実機確認

この文書は汎用の確認手順です。実施結果・未確認事項は末尾の版別記録に残し、チェック項目を無条件に完了扱いにしません。
破壊的なテストには実データ端末を使わず、先に[JSONバックアップ](backup.md)を確保してください。

## 自動テスト

[開発ガイド](development.md)に従い、JDK 17とテスト用Java 21、SDKを用意して実行します。

```sh
./gradlew testDebugUnitTest assembleDebug lintDebug
python3 -m unittest discover -s tools/tests -v
bash tools/check-workflows.sh
```

AndroidテストはRobolectric・Fakeを使い、実GPS・外部天気APIへ接続しません。
API 28/31/36の位置取得、API 33のGeocoder、Room移行・投稿・ViewModel・JSON往復と失敗/キャンセルを検証します。
Pythonは公開判定・版・署名/配布のガード、actionlintはWorkflowのYAML・式・Action参照を検証します。
UIの表示・OSサービスの実際の取得成功率・端末上の更新互換性は別途実機またはエミュレーターで確認します。

## 投稿・保存・表示

1. 空状態から日本語・改行・絵文字で投稿し、本文と端末のローカル日時を確認します。空白だけは送信できないことも確認します。
2. IME表示・長文でも入力欄と送信ボタンを操作でき、本文上限を超えた入力が保存されず残ることを確認します。
3. 新しい投稿は下に並び、古い履歴を読んでいる間に編集・属性到着で不意にスクロールしないことを確認します。
4. 画面回転で下書きが残り、編集で作成日時・ID・順序が変わらず、削除キャンセルでは投稿が残ることを確認します。
5. 強制終了・アプリ再起動・端末再起動後に本文・編集・削除結果が残ることを確認します。
6. 日付を跨ぐ投稿、同時刻の多件数、タイムゾーン変更後の日時表示を確認します。

## 位置・天気

1. 初期OFFで権限を勝手に求めず、設定ON操作でおおよその位置だけを要求することを確認します。
2. 許可して新規/連続投稿し、本文先行保存、属性の追記、設定の最終結果（候補状態・待機・再試行・終了理由）を確認します。
3. 権限拒否・取消、位置OFF、機内モード、通信遅延、地名サービス非対応でも本文・編集・削除を妨げず、権限を繰り返し要求しないことを確認します。
4. 取得前に本文を編集・削除し、遅延結果が上書き・復活させず、次の入力もできることを確認します。
5. 取得中に画面離脱・設定OFFとし、本文が残り、古い投稿へ再開後の一括補完が起きないことを確認します。

丸めた座標の外部送信と、出典・利用条件の導線も確認してください。取得条件・期限は[位置・天気](location-weather.md)を参照します。

## バックアップ・復元

1. 端末内と利用するクラウドのファイル選択UIで保存・読み取りを確認し、件数と内容を照合します。利用しないプロバイダーは対象外と理由を記録します。
2. 保存キャンセル、容量不足、プロバイダー切断・書き込み/クローズ失敗で成功表示しないことを確認します。
3. テスト用インストールでJSONを読み、確認キャンセルで元データが残り、承認した場合だけ全件置換されることを確認します。
4. 日本語・改行・絵文字・長文・null属性・同時刻順序・IDが復元後も一致し、新規投稿もできることを確認します。
5. 不正JSON、未知スキーマ、重複ID、空データでの既存記録消去を拒否し、失敗時に元DBを保持することを確認します。
6. ファイル選択中や確認中の画面回転・プロセス再作成で勝手に置換されず、属性到着と復元が競合しても古い結果が混入しないことを確認します。

## 署名と更新

- 鍵とパスワードの別媒体保管・読み出し確認は初回／鍵変更時に記録します。秘密値は確認記録へ貼りません。
- 配布APKのチェックサムと公開証明書の固定値を照合します。署名不一致を解消するために、未退避の実データを消さないでください。
- 同一署名・applicationId・増加するversionCodeの候補を`adb install -r`で上書きし、本文・日時・順序・位置/天気・設定とJSON往復を確認します。
- Roomスキーマ移行の確認では旧スキーマのデータを持つテスト端末へ、同じ署名の新スキーマ対応APKを上書きし、既存投稿が保持されることを確認します。DB番号とアプリの版番号は区別します。

[公開・署名・更新](releasing.md)、[ADB導入](development.md)に具体的な手順があります。

## アプリの更新

API 26/36の自動テストで版/資産/URLの検査、上限・中断・HTTP失敗、実署名APKと改ざん/別署名の拒否、FileProviderの限定公開、許可と再検証を確認します。
実機ではv0.1.3を手動導入後、次の正式版に対して確認・取得・許可画面・OS承認/取消・上書きと記録保持を確認します。初回のv0.1.3リリースでは完全な自己更新成功を確認済みとしません。
[更新ガイド](updating.md)を参照し、署名不一致をアンインストールで解決しないでください。
