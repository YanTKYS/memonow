# 位置・天気とプライバシー

投稿画面右上の「設定」→「位置・天気」から有効にします。説明を読んでONにしたときに限り、
`ACCESS_COARSE_LOCATION`（おおよその位置）を要求します。精密位置・バックグラウンド位置の権限は要求しません。
拒否後は自動で再要求せず、利用したい場合のみ端末のアプリ設定で許可して戻り、ONにしてください。
権限が取り消されていれば、画面の再表示時に自動付与をOFFにします。拒否しても本文を投稿できます。

- 本文と投稿日時をまずRoomへ保存し、入力をクリアした後に、保存済みIDへ属性を非同期追記します。
  メタデータ取得中も次の投稿を入力・送信できます。編集済みの本文や作成日時・順序は変更せず、削除済み投稿を復活させません。
- 投稿時だけ位置を取得します。利用可能なプロバイダーのキャッシュが経過2分以内・推定精度10km以内なら利用し、
  有効なキャッシュがなければAPI 30以降は `LocationManager.getCurrentLocation()`、API 26〜29は最初の更新で解除するリスナーを利用します。
  API 31以降では有効なFusedとNetworkを最大2件並行で試し、最初の有効な位置を採用して残りの要求を解除します。GPSの精密位置は要求しません。
  各候補の待ちは最大10秒です。上位の位置取得期限25秒も維持します。古い・未来時刻・精度不明／10km超の位置は使いません。
  1試行のOS要求は最大2、再試行込みで投稿当たり最大4要求です。同時処理は2投稿なので同時のOS要求は全体最大4です。
  完了・タイムアウト・中断時にリスナー／CancellationSignalを解除し、常時追跡はしません。
- 座標は小数2桁（約1km単位、緯度で距離が変わります）に丸め、Android Geocoderと
  Open-Meteoへ渡します。Geocoderへは住所ではなく座標を渡し、市区町村・都道府県の名前だけを採用します。
  道路名・建物名・詳細住所は保存しません。Androidの地名解決サービスも通信する可能性があります。
- 座標は一時的なメモリ上だけで使用し、DB・設定・永続ジョブには保存しません。
  外部へ本文・投稿履歴・投稿IDを送信しません。サービス側には丸めた座標とIPアドレスが伝わります。
  Open-Meteoは座標を含み得るアクセスログを最大90日保持すると利用条件に記載しています。
- 地名解決は3秒、天気取得は6秒の待ち時間上限を設け、HTTP接続・読み込みにも各3秒のタイムアウトを設定しています。
  OSの地名解決が非対応・空結果・失敗でも天気取得を続けます。地名だけ／天気だけ取得できた場合も保存します。
- 自動付与OFF・権限なし・位置未取得では天気APIへアクセスしません。位置設定OFF・機内モード・通信エラー時も
  本文は正常な記録として残り、取得できない属性は空欄になります。属性の取得失敗は再投稿の必要を意味しません。
- 画面を離れた場合・アプリ終了・自動付与OFF時は取得を中断します。過去投稿の一括補完や永続的な再試行は行いません。
  同時取得は最大2件、追加6件を最大30秒待機させます。枠・待機期限を超えた場合は属性を省略し、本文は残します。
  一時的な失敗だけ2秒後に1回再試行し、付与済み側は再取得しません。位置未取得なら位置を再試行し、地名・天気だけの失敗は有効な丸め済み一時座標を再利用します。経過時間込みで位置の鮮度を確認し、期限切れなら終了します。投稿後2分を超えたものは対象外です。
  OFFにしても保存済みの属性は消しません。
- 天気はOpen-Meteoの15分間隔のモデルによる**推定値**です。UTC時刻・単位・値を検証し、投稿時刻とのずれが
  20分を超える応答は保存しません。推定の時点を `weatherAt` に保持します。不明な天気コードは無理に分類せず、欠損値は表示しません。

設定の「最後の自動付与結果」で、位置待機・地名取得・天気取得・DB追記と結果を確認できます。
権限なし、位置OFF／利用可能なプロバイダーなし、位置の期限・鮮度・精度、地名非対応／失敗、
天気通信／HTTP／応答不正／時刻差などを区別します。並行処理では最新の投稿開始に対応する結果だけを表示します。
設定OFF・画面離脱・復元による中断も表示し、再開時に過去投稿を再取得しません。
位置候補ごとのキャッシュ採用可否、位置なし応答、期限内の応答なし、採用・他候補採用による解除も固定ラベルで確認できます。結果は当該の位置試行にひも付くスナップショットで、並行する別投稿の候補状態とは混ざりません。
診断はメモリ内の固定ラベルだけで、投稿別の履歴や座標・本文・URL・例外ログを保存・送信しません。
アプリのプロセス終了で診断は消えます。取得済みの属性は投稿に残ります。

確認手順は[テストガイド](testing.md)、版ごとの実施結果は[確認記録](testing.md)を参照してください。
Android 13以降のGeocoderは非同期APIで、未完了のOS要求は最大2件に制限します。旧版は専用1スレッド・キュー1件に制限し、OS呼び出しがブロックしても期限で地名を打ち切って天気へ進みます。
HTTP 429/5xx、位置や地名の一時失敗などを有限再試行の対象とし、他のHTTPエラー・不正応答・時刻差・権限/設定OFF・地名非対応は繰り返しません。

### 出典・利用条件

**Weather data by [Open-Meteo.com](https://open-meteo.com/)** — [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。
WMO天気コードを簡潔な日本語に変換して表示します。アプリの設定画面にも出典とライセンスの導線があります。

利用APIはHTTPSの [`/v1/forecast`](https://open-meteo.com/en/docs) です。
送信するのは丸めた座標と `current=temperature_2m,weather_code`、摂氏・UTC epoch秒の指定だけです。
APIキー・自前サーバ・アカウントは不要です。通常のネットワーク権限 `INTERNET` は天気通信に使用します。
[無料APIの利用条件・プライバシー](https://open-meteo.com/en/terms)は非商用利用限定で、
1日10,000回未満・1時間5,000回・1分600回の制限があります。
現在の個人利用向け構成を商用利用・広告付き配布等へ転用する場合は、提供元の条件と契約を再確認してください。
