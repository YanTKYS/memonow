# v0.1.2 確認記録・位置取得の分析

[Issue #23](https://github.com/YanTKYS/memonow/issues/23)のv0.1.1実機診断は「位置取得タイムアウト・2回目上限」です。
今回の失敗が位置フェーズであることは確認済みです。端末側の原因、権限不足・通信遮断・天気API障害とは断定しません。

| 経路 | 判定・変更 |
| --- | --- |
| 既存キャッシュ | 有効な候補の中で最も新しい位置を優先。古い／未来時刻・不正確・不正な座標は拒否し、候補ごとに固定ラベルを表示 |
| Fusedの応答なし・遅延 | 旧版はNetworkを始めるまで最大10秒。新方式ではNetworkも同時開始し、他方の有効位置を直ちに採用 |
| null応答 | 位置なし応答と無応答タイムアウトを区別。他方の進行は止めない |
| 不正・精度不足の応答 | 採用せず他方を待つ。精度条件を緩めない |
| 両候補が無応答 | 各10秒で終了。逐次20秒待つ方式より短縮。上位25秒・2秒後の有限再試行は増やさない |
| 位置サービスOFF・候補なし／消失・権限なし | 既存ガードで終了し、候補状態を固定ラベルで表示 |
| 成功・中断・期限切れ | 残りのCancellationSignal／旧APIのリスナーを解除。常時追跡・永続再試行なし |

Google Play servicesは追加しません。標準OS APIでCOARSEのみを使い、端末のGMS有無や新しい位置権限に依存せず最小変更で競争的取得を実現します。
1試行のOS要求は最大2、再試行込みで投稿当たり最大4要求です（旧方式と同じ上限）。同時のOS要求は投稿当たり最大2、投稿処理は同時2件のため全体最大4です。成功時には残りを解除し、OS側の電力・位置計算を不必要に継続させません。
同時要求による端末固有の電力・サービス挙動は実機未確認です。単なる時間延長や権限追加による対処ではありません。
