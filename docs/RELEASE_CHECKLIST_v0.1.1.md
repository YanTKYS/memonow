# v0.1.1 公開前の確認記録

v0.1.0の公開後、属性が付く投稿と付かない投稿が混在するという[Issue #19](https://github.com/YanTKYS/memonow/issues/19)の報告を受けた修正版です。
実機の失敗経路は未特定です。本版の実機確認と0.1.0→0.1.1更新時のデータ保持は未実施のため、ノートはdraftです。

## コードとFakeで再現する失敗経路

| 経路 | 両方欠ける理由・対策 |
| --- | --- |
| 位置タイムアウト・キャッシュの鮮度／精度不適合 | 地名・天気共通の前提がない。有限再試行で位置を取り直す |
| 連続投稿のBUSY | 旧版は2件を超えると即省略。2件処理＋6件待機・30秒上限へ変更 |
| 画面離脱・権限／設定OFF | キャンセルで欠け得る。追跡防止のため維持し、再開後の取り直しはしない |
| 地名・天気の失敗 | 地名のみ失敗しても天気を続ける。両サービスが失敗すれば両方欠け得る。取得済み側を保った再試行 |
| 投稿後2分・天気時刻差・不正応答 | 過去時点の情報を偽装しないため拒否。時間不一致・不正応答は繰り返さない |
| 削除・復元・古いJobの遅延結果 | DB世代・キャンセル・投稿存在の確認で破棄。既存属性も上書きしない |

全投稿に取得を保証する変更ではありません。位置の待機25秒・地名3秒・天気6秒の各期限は維持し、処理全体を初回＋再試行1回に限定します。
2秒の間隔、最大30秒のキュー待ちも投稿後2分の予算内です。無制限キュー・永続ジョブ・過去投稿の走査はありません。
診断は固定ラベルの一時状態だけで、本文・座標・URL・個人ID・生ログ・投稿別の永続履歴は保持しません。
