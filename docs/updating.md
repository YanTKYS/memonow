# アプリから更新する

設定 → **アプリの更新**でインストール済みの版とcodeを確認し、「最新版を確認」を押します。
GitHubの固定リポジトリの公開済み正式Releaseを匿名で照会します。起動時の自動確認・自動取得はありません。
新しい版の場合だけ「更新する（APKを取得・検証）」を表示します。同一版・古い版・情報不正・通信失敗はメッセージで区別します。

1. 大切な記録を先にJSONへ保存します。
2. 「更新する」でAPKを取得します。進捗を表示し、取消できます。画面を離れると処理を中断します。ブロック中の通信は接続/読み取りの期限後に取消が完了する場合があります。
3. 検証できた場合だけインストーラーを開けます。Android 8以降でこの提供元からのインストールが未許可なら、専用ボタンから端末の「この提供元のアプリを許可」へ進み、利用者自身が選択して戻ります。
4. 「インストーラーを開く」を押し、Android標準画面で承認・取消します。アプリ側の表示はOS画面への引き渡しまでで、インストール成功を自動で断定しません。

このため `REQUEST_INSTALL_PACKAGES` を宣言しています。許可を自動変更したり、強制インストールやアンインストールで解決したりしません。
通常の上書き更新とOS確認の取消は端末記録を保持します。失敗時は「正式Releaseをブラウザで開く」から配布案内を参照できます。

## 取得・検証

- 最新版APIは `https://api.github.com/repos/YanTKYS/memonow/releases/latest` 固定。認証情報・APIキーは不要です。
- 正式版のtagは厳密な `vX.Y.Z`、APK名は `memonow-vX.Y.Z.apk` とし、重複・欠損・不正なサイズ/URLを拒否します。APIメタデータは1MiB、APKは64MiB上限で、APKはストリーミング保存します。
- APKは固定リポジトリの該当版のdownload URLだけを開始点とします。HTTPSを維持し、転送先はGitHub所有の配布ホストの許可リスト内だけ、最大5回の転送です。TLS検証は無効にしません。
- 正式assetの `sha256:` digestが必要です。サイズとハッシュの一致に加え、Android公式ツール由来の`apksig`（Apache License 2.0）でAPK署名を暗号学的に検証します。PackageInfoの署名表示だけを信用しないための依存です。
- applicationId、versionName、現在より大きいversionCode、現在インストールされている署名証明書との完全一致を要求します。鍵ローテーションや別署名を自動で許容しません。OSの最終判定でも上書き条件を検査します。
- 更新画面ごとに一意なファイル名を使い、別画面の取得・取消と干渉させません。検証前のファイルはアプリ専用cacheの部分ファイルに保存し、不整合・失敗・取消で破棄します。検証済みファイルだけ別フォルダーへ移し、非exportedのFileProviderから読み取り専用URIをインストーラーに渡します。
- OSへの引き渡し前には再検証します。引き渡し後はOSが読むためファイルを残し、同じ画面での次の確認時に削除します。別画面・別プロセスから残った検証済みAPKは下記の期限で整理します。24時間を超えた残存APKは更新画面用ViewModelの作成時にも削除します。プロセス終了等で残った部分ファイルも同時に整理します。

投稿・座標・履歴・Secretsは送信しません。GitHubと配布ホストには通常の通信に伴うIPアドレス等が伝わります。
APIレート制限・404・資産不備・容量不足・通信中断・検証不一致は更新を中止し、未検証APKをOSへ渡しません。

### 署名検証ライブラリの対応範囲

`apksig 8.13.2`は[上流README](https://android.googlesource.com/platform/tools/apksig/+/refs/heads/main/README.md)で端末外向けとされており、Android上での公式サポートを意味しません。APKの署名を暗号学的に検証し、現在の署名証明書と照合する目的で版を固定して採用しています。OSインストーラーによる最終検証も必要です。

互換性はJVMテストと分け、CIの`APK signature on Android API 26/36`でAndroidプロセス内のinstrumented testを実行します。インストール済みdebug APKのコピーを実際の`ApkVerifier.verify()`と製品の`UpdateVerifier`に渡し、検証成功とPackageManagerが返す署名証明書との一致を検査します。署名対象の1バイトを変更し、SHA-256を計算し直したAPKも拒否することを検査します。

この確認はAPI 26/36のGoogle APIs x86_64エミュレーターが対象です。中間API・すべてのOEM端末の保証や、OSインストール完了の確認ではありません。ライブラリ更新時もこのCIを実行し、未確認の版へ自動更新しません。テストはCI用debug署名だけを使い、正式署名鍵・実利用の記録・正式版の上書き更新を必要としません。

## 導入時の制限と確認

この機能はv0.1.3以降です。既存v0.1.2からv0.1.3へは[正式Release](https://github.com/YanTKYS/memonow/releases/latest)から手動更新します。
自己更新の実機導線はv0.1.3以降からさらに新しい版への更新で確認します。初回リリース時点で完全な自己更新実機成功は確認していません。
debug APKと正式版は署名が異なる場合があり、アプリからの上書きも拒否します。記録を残したまま[移行・バックアップ](backup.md)を確認してください。
OS/OEMごとの許可画面・インストーラーの動作と、更新/取消後のデータ保持は実機での確認対象です。
